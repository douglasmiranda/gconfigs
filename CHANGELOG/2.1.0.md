# 2.1.0 - 2026-10-27

## What's New

- `cast=list`, `cast=tuple` and `cast=set` accept a single value without separator: `DOMAINS=domain.com` -> `["domain.com"]`.
- Empty or whitespace-only values cast to an empty list, tuple or set.

## Fixes

- `len()` works on every backend, including `local_files`, `ini_file` and `toml_file` (it raised `TypeError` before).
- String values are stripped before casting, so mounted secret files ending with a newline (e.g. `true\n`) can be cast.
- `default=None` is returned as is instead of going through the cast (`envs("PORT", default=None, cast=int)` raised `ValueError`).
- INI files: sections and options with dots in their names (e.g. `[app.db]`) can be read and iterated.
- INI files: values containing `%` (e.g. passwords) no longer raise `InterpolationSyntaxError`.
- Dotenv files: `export KEY=value` lines are supported.
- Dotenv files: one pair of matching quotes around a value is removed (`KEY="value"` -> `value`).
- TOML files: quoted keys containing dots (e.g. `[servers."alpha.example.com"]`) can be read and iterated.

## Behavior Changes

These are bug fixes, but you may notice them if you relied on the old behavior:

- A list/tuple/set cast of a value without separator returns a single item instead of raising `ValueError`. Strings starting with `[` must still be valid JSON.
- Dotenv values wrapped in matching quotes are returned without them.
- INI values are read literally: `%(name)s` is no longer expanded.
- With `strip=True` (the default), custom cast functions now receive the stripped value.
